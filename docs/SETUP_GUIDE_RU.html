Полный запуск без Docker

Один практический гайд от чистого каталога до работающих Web, API, PostgreSQL, Worker/QA, Telegram Bot, Discord Bot и Gmail API. Все команды рассчитаны на Windows PowerShell и текущую архитектуру проекта.

1. Требования

Для локального запуска нужны Node.js 22+, npm, Git и PostgreSQL. Docker, Docker Desktop и docker-compose проекту не требуются.

node -v
npm -v
git --version
psql --version
Если psql не найден, это не означает, что PostgreSQL не установлен. Проверь службу Windows и при необходимости добавь каталог PostgreSQL bin в PATH.

2. Проект

cd C:\CustomApps\Projects\voidcript_platform
Test-Path .\package.json
Test-Path .\.env.example

Ожидаемый результат для двух последних команд — True.

Установи зависимости:

npm install

Test-Path .\node_modules
Test-Path .\node_modules\.bin

Проверка без раскрытия secrets

$envFile = ".env"
$keys = @(
  "DATABASE_URL","INITIAL_OWNER_EMAIL","INITIAL_OWNER_USERNAME","INITIAL_OWNER_PASSWORD",
  "INITIAL_OWNER_TELEGRAM_ID","INITIAL_OWNER_DISCORD_ID","GITHUB_REPOSITORY_URL","GITHUB_TOKEN",
  "NEXT_PUBLIC_TURNSTILE_SITE_KEY","TURNSTILE_SITE_KEY","TURNSTILE_SECRET_KEY",
  "TELEGRAM_BOT_TOKEN","TELEGRAM_OWNER_ID","DISCORD_BOT_TOKEN","DISCORD_GUILD_ID",
  "DISCORD_NOTIFICATION_CHANNEL_ID","DISCORD_WEBHOOK_URL","DISCORD_CLIENT_ID","DISCORD_CLIENT_SECRET",
  "GMAIL_CLIENT_ID","GMAIL_CLIENT_SECRET","GMAIL_REFRESH_TOKEN","GMAIL_FROM",
  "ENCRYPTION_KEY","API_INTERNAL_SECRET","BOT_SHARED_SECRET"
)
$map = @{}
Get-Content $envFile | ForEach-Object {
  if ($_ -match '^\s*([^#=\s]+)\s*=(.*)$') { $map[$matches[1]] = $matches[2] }
}
foreach ($key in $keys) {
  if ($map.ContainsKey($key) -and -not [string]::IsNullOrWhiteSpace($map[$key])) {
    Write-Host "[OK]   $key" -ForegroundColor Green
  } else {
    Write-Host "[MISS] $key" -ForegroundColor Red
  }
}

4. PostgreSQL

Проверь Windows service:

Get-Service | Where-Object { $_.Name -like "postgresql*" }

Нужен статус Running.

Проверь подключение напрямую через полный путь, если psql не добавлен в PATH:

& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U voidcriptui -h 127.0.0.1 -d voidcriptui

После ввода пароля:

SELECT current_user;
SELECT current_database();
\q
Ожидаемо: current_user = voidcriptui и current_database = voidcriptui.

5. Prisma и база приложения

Новая версия проекта загружает root .env перед Prisma workspace-командами, поэтому сначала:

npm run db:generate
npm run db:push
npm run db:seed

Порядок важен. Если db:push сообщает Environment variable not found: DATABASE_URL, не запускай seed — сначала проверь root .env.

После успешного db:push ошибка The table public.Permission does not exist при seed исчезает.

Для повторного первого запуска есть автоматический сценарий:

powershell -ExecutionPolicy Bypass -File .\scripts\windows\first-run.ps1

6. Gmail API вместо SMTP

Проект использует Gmail API OAuth 2.0. SMTP-поля удалены из актуального шаблона.

В Google Cloud:

https://console.cloud.google.com/
  1. Создай проект.
  2. Enable: Gmail API.
  3. Google Auth Platform → Branding → заполни название и контакт.
  4. Audience → External → добавь свой Gmail в Test users.
  5. Data Access → добавь https://www.googleapis.com/auth/gmail.send.
  6. Clients → Create OAuth client → Web application.
  7. Для OAuth Playground временно добавь redirect https://developers.google.com/oauthplayground.

В OAuth Playground открой:

https://developers.google.com/oauthplayground/

Используй собственные credentials, укажи scope:

https://www.googleapis.com/auth/gmail.send

После авторизации и обмена code на tokens сохрани Refresh token в:

GMAIL_REFRESH_TOKEN=...

GMAIL_FROM — адрес твоего Gmail.

Не публикуй refresh token. Не вставляй его в NEXT_PUBLIC_* и не коммить в Git.

12. HTTPS

Локально: HTTPS не нужен для первого запуска. http://localhost:4080 и http://localhost:8100 нормальны.

Для localhost TLS: можно использовать mkcert.

choco install mkcert
mkcert -install
mkdir certs -Force
mkcert -key-file certs\localhost-key.pem -cert-file certs\localhost.pem localhost 127.0.0.1 10.6.7.1

Но для production проще терминировать TLS на Netlify/Cloudflare/NGINX, а Node оставить на HTTP localhost-портах.

13. Netlify

Для frontend подключи GitHub repository WorkAccount211/VoidCriptUI-Platform.

Проект содержит netlify.toml. Production web build должен собираться из workspace apps/web через root command.

После успешного локального build:

git status
git add .
git commit -m "Fix first-run configuration and build"
git push origin main
Netlify выдаст HTTPS для своего домена. Однако frontend на Netlify не должен обращаться к localhost:8100 в production. Production API обязан иметь публичный HTTPS URL.

14. Ploi / NGINX

Для production API подними VPS через Ploi, установи Node.js и PostgreSQL/подключись к существующей БД. Не публикуй порт 8100 напрямую, если можно поставить reverse proxy.

cd /home/ploi/voidcriptui-platform
npm ci
npm run db:generate
npm run db:push
npm run build
pm2 startOrRestart ecosystem.config.cjs --update-env
pm2 save

Типовая схема:

https://api.<your-domain> → http://127.0.0.1:8100

Web может оставаться на Netlify:

https://<your-site>.netlify.app → Netlify HTTPS
https://api.<your-domain> → Ploi/NGINX HTTPS → API :8100

15. PM2

npm install -g pm2
npm run build
pm2 startOrRestart ecosystem.config.cjs --update-env
pm2 save
pm2 status
pm2 logs

Для Windows PM2 подходит для локального/серверного запуска, но production VPS обычно проще обслуживать через Linux + Ploi.

16. Типичные ошибки

Environment variable not found: DATABASE_URL

Запускай обновлённый npm run db:push из корня. Workspace script теперь загружает root .env.

public.Permission does not exist

Сначала npm run db:push, потом npm run db:seed.

Could not find a declaration file for module qrcode

В обновлённом проекте добавлен @types/qrcode. После распаковки снова выполни npm install.

Web build — error в docs/page.tsx

Обновлённый файл использует строгий тип LucideIcon, а не tuple-массив с неоднородным типом.

Telegram: ctx.from is possibly undefined

Обновлённый bot проверяет ctx.from до использования.

Discord/Telegram говорят token missing

Боты теперь ищут root .env через абсолютный путь от исходного файла и fallback из текущего каталога. Проверь, что запускаешь проект из корня.

Netlify — Next build не видит проект

Убедись, что в repository есть netlify.toml и что build command запускает npm run build:web.

17. Security

  • .env не коммитить.
  • GMAIL_REFRESH_TOKEN, Discord/Telegram tokens и Turnstile secret — только server-side.
  • NEXT_PUBLIC_* использовать только для действительно публичных значений.
  • Owner/Admin MFA обязательна.
  • Recovery codes хранить как секрет.
  • Не выполнять произвольный Lua/plugin code на сервере.
  • Production API размещать за HTTPS reverse proxy.
Важно: если secret когда-либо попал в GitHub, лог deploy или публичный чат, считай его скомпрометированным и создай новый credential.
